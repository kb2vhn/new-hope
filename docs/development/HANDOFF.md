# New Hope — Development handoff (architecture reconciliation 2026-10-16)

**Repository:** https://github.com/kb2vhn/new-hope. **Implementation status:** documentation only, no gate G0–G5 complete. **Initial test target:** x86-64 QEMU then a physical Lenovo IdeaPad; build from the workstation. ARM64 later on hardware to be chosen. No disk modification or bootloader/keys chosen.

New Hope is a single independent portable Rust microkernel OS, not a MINIX fork, Linux/FreeBSD distribution, or automatically POSIX. Kernel owns CPU scheduling, interrupts/exceptions, physical/virtual memory mechanisms, primitive IPC and small mandatory UMI enforcement. All external-to-kernel and external-to-external message operations require UMI authorization. Kernel internals and CPU interrupts are not UMI messages; UMI does not require TCP/IP. Protected user-space services own policy administration, filesystem ACLs, networking, drivers, command prompt, identity and logs.

**Critical product/security direction:** UMI is like an efficient, configurable firewall/ACL engine—identity, destination, operation, deny precedence, bounded state, audit—not hardcoded knowledge of browsers, file paths or encrypted traffic. Application children may hold equal or less authority, never more; the kernel prevents takeover/detachment/reparenting and terminates the full descendant tree on parent exit, failure, or kill. Separately launched protected services stay under their own authorized supervisors. A protected user-space networking service performs native stateful firewall enforcement; UMI permission doesn't override an explicit firewall denial. Browser extensions/origins/cookies belong exclusively to the browser. HID global capture and similar invasive capabilities require independent authorization.

**Additional approved requirements:** owner/creator distinction, independent Traverse/List/file Read/file Execute, no world 777, private file creation, metadata-only administration until separately journaled takeover; separate OPS, DR, SecAuditor local accounts, restricted `doas`/`eu -` elevation and 10-minute maximum/default as configured, DR-reviewed account-wide `SECURITY_LOCKED` with frozen attributed tasks. Boot-only RECOVERY uses a once-shown random 26-character alphanumeric code to reset OPS/DR/SecAuditor credentials or create admin, but **never unlock a security-locked account**. Backup is owner-opt-in for personal data, with protected operator/services and separate restore-original right; shared `/projects` and system-state recovery policy distinct. Administrative/litigation holds preserve eligible scope and SecAuditor only reads held data. Security journals rotate 7 days / 128 MB and retain 90 days by default, with protected hold/incident records and a DR-only configurable 10% anomaly value (**basis not decided**).

**Open rather than invented:** bootloader/ABI/capabilities, disk format, anomaly baseline, hold activation/release owner, scope of SecAuditor Execute, post-recovery process disposition and actual hardware secure-boot coverage.
